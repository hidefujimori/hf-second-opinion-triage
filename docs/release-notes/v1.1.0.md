# HF Decision Model Triage and Second Opinion App v1.1.0

Changes since **v1.0.0**. Package: `second_opinion_triage-1.1.0.spl`
(SHA-256 `d55b2c8c619fe4d850318359367784a6ed9629ecc212436fb86e8b1596603cc6`).
AppInspect (precert, all checks and cloud tags): 0 failures, 0 errors.

## Highlights

### Analysts never receive the API keys
- New REST endpoint `/services/second_opinion_triage/call` (capability `jev_triage_run`). Analysts' searches send
  the facts and questions (or the prompt) and get back only the answer; the endpoint reads the keys and the Setup
  settings itself. The caller cannot choose the endpoint, model, proxy or key.
- The `/services/second_opinion_triage/keys` endpoint of 1.0 is gone. Admins still call the providers directly
  (needed for the evaluation options).
- This removes the 1.0 known limitation "users with `jev_triage_run` can receive this app's keys".

### Re-triage with the analyst's statements
- For an Undetermined finding, an analyst can pick up to 3 statements of what they know and the SIEM does not:
  approved change, confirmed with the account owner, authorized security test, source is our own network, account
  or host known to be compromised, part of an incident being handled. Admins can add their own on
  **Setup > Analyst statements**.
- The decision model takes the statements as true and does not check them against the facts (measured on labelled
  findings). So the same run also computes the result **without** the statements, and a **warning** is shown when
  the facts alone point to a true positive but the statements moved the result away from it.
- Every attempt is kept and written to the ES finding as a Note (who, which statements, the result without them,
  the warning). The final decision stays in ES.
- Command: `jevtriage statements=<ids> persist=true`; list: `| jevstatements`.

### Translation of the ES AI SOC Analyst text
- On the Japanese page, the ES AI column can translate the summary and justification, or everything (evidence,
  details and every check), with the app's LLM. The translation is stored, shared and reused until ES AI writes a
  new analysis, and is never sent to the decision model.
- Long texts are split and translated in parallel; a piece the LLM leaves out stays in English.
- Command: `| jevtranslate id=<finding> scope=short|full lang=ja`.

### Dark theme
- The app pages follow the user's Splunk theme (`supported_themes = light,dark`), with colours adjusted for dark.

### Smaller changes
- `usekey=` is listed in the admin-only message.
- Setup shows "Nothing counted today. Last counted day (date)" instead of "Used today" for an older day.

## Upgrade from 1.0.x
1. Apps > Manage Apps > *Install app from file* > `second_opinion_triage-1.1.0.spl`, tick *Upgrade app*.
   On Splunk Cloud: Apps > Upload app. Restart Splunk if asked.
2. Nothing to configure. Analysts keep the role `jev_triage_user`.

Settings and results are kept.

## Requirements
- Splunk Enterprise 10.x with ES 8.7, or Splunk Cloud with ES 8.7.
- A key for the decision model (TypeSafe Jev by default) and, for explanations and translations, an LLM key — your
  own keys, billed by those providers.

## Tested on
- Splunk Enterprise 10.4.2 + ES 8.7.1 (BOTS v3 data, 33 labelled findings), Jev 1.13: disposition 32/33, no true
  positive missed, urgency 31/33, within one level 33/33 — the same for admins and for analysts through the endpoint.
- Splunk Cloud 10.4 + ES 8.7.1: translation (admin and analyst), dark theme.

## Known limitations
- Statements are taken as true by the decision model: read the warning and the result without them.
- Translation quality and speed depend on the LLM; a small model may leave a piece out (shown in English).
- The triage list runs ES's `notable` macro over all findings in the time range and can take about 10 s on a large
  Splunk Cloud stack.
- Threat intelligence matches cover source IP addresses only.

## 主な変更

### アナリストが API キーを受け取らなくなりました
- 新しい REST エンドポイント `/services/second_opinion_triage/call`（権限 `jev_triage_run`）。アナリストの検索は事実と質問
  （または指示文）を送り、答えだけを受け取ります。キーと Setup の設定はエンドポイントが自分で読みます。呼び出し側は
  送り先・モデル・プロキシ・キーを選べません。
- 1.0 の `/services/second_opinion_triage/keys` はなくなりました。管理者はこれまでどおり直接呼びます（評価用の
  オプションに必要なため）。
- 1.0 の既知の制限「`jev_triage_run` を持つユーザーはこのアプリのキーを受け取れる」を解消しました。

### アナリストの申告をもとにした再トリアージ
- 判別不可の Finding に、SIEM にはない自分が知っていることを3つまで選んで再トリアージできます: 承認済みの変更・作業、
  本人に確認済み、承認済みのセキュリティテスト、送信元は自組織のネットワーク、侵害が分かっているアカウント・ホスト、
  対応中のインシデントの一部。管理者は **Setup > アナリストの申告** で独自の申告を追加できます。
- 判定モデルは申告を正しいものとして扱い、事実と突き合わせません（正解付きの Finding で測定）。そのため同じ実行で
  申告**なし**の判定も出し、事実だけでは TP を示すのに申告で結果が TP から離れたときは**警告**を出します。
- 試した内容はすべて残し、ES の Finding に Note として書きます（誰が、どの申告で、申告なしの判定、警告）。
  最終判断は ES で行います。
- コマンド: `jevtriage statements=<id> persist=true`、一覧: `| jevstatements`。

### ES AI SOC Analyst の文章の翻訳
- 日本語の画面で、ES AI の列の「要約と根拠」または「すべて」（証拠・詳細・すべての確認）をアプリの LLM で翻訳できます。
  訳は保存して全員で共有し、ES AI が新しい分析を書くまで使い回します。判定モデルには渡しません。
- 長い文章は分けて並行して訳します。LLM が答えに含めなかった部分は英語のまま表示します。
- コマンド: `| jevtranslate id=<Finding> scope=short|full lang=ja`。

### ダークテーマ
- アプリの画面が Splunk のテーマに合わせて表示されるようになりました（`supported_themes = light,dark`）。暗い背景用に色を調整しています。

### 小さな変更
- 管理者専用のメッセージに `usekey=` を追加。
- Setup の使用量で、今日の分がないときは「本日はまだ使用していません。最後に数えた日（日付）」と表示。

## 1.0.x からのアップグレード

   Splunk Cloud では Apps > Upload app。再起動を求められたら再起動します。
2. 設定は不要です。アナリストのロールは `jev_triage_user` のままです。

設定と結果はそのまま残ります。

## 動作環境
- Splunk Enterprise 10.x ＋ ES 8.7、または Splunk Cloud ＋ ES 8.7。
- 判定モデルのキー（既定は TypeSafe Jev）と、説明・翻訳を使う場合は LLM のキー（ご自身のキー、各社の料金）。

## 検証した環境
- Splunk Enterprise 10.4.2 ＋ ES 8.7.1（BOTS v3 のデータ、正解付き Finding 33件）、Jev 1.13: Disposition 32/33、TP の見逃し
  なし、Urgency 31/33、1段階以内 33/33。管理者でも、エンドポイント経由のアナリストでも同じ。
- Splunk Cloud 10.4 ＋ ES 8.7.1: 翻訳（管理者・アナリスト）、ダークテーマ。

## 既知の制限
- 判定モデルは申告を正しいものとして扱います。警告と申告なしの判定を確認してください。
- 翻訳の質と速さは LLM しだいです。小さなモデルは一部を省くことがあります（英語のまま表示）。
- トリアージ一覧は期間内のすべての Finding に ES の `notable` マクロを流すため、大きな Splunk Cloud では約 10 秒かかります。
- 脅威インテリジェンスの照合は送信元 IP アドレスだけです。
