Changes since **v0.9.14-beta**. Package: `TA-jev-triage-0.10.3.spl`
(SHA-256 `d416a28ec1451ca77407a92f0d440524b38072350cac2e8ffffd58c2bb800216`).
AppInspect (cloud tags, precert): 0 failures, 0 errors, 0 manual checks.

## Highlights

### Support mode: editing the Jev questions (0.10.0 – 0.10.3)
The questions sent to Jev are locked. When support needs to change their wording, an admin
(`edit_storage_passwords` or `admin_all_objects`) opens **Setup > Prompts (support)**:

1. **Start support mode** with a reason and a time limit (default 4 hours, at most 24). The lock comes back
   when the time is up or someone clicks *End support mode*; versions already applied stay in use.
2. **Edit** the shipped questions or a saved version and **save a draft**. Only the wording can change
   (instructions, choice descriptions, urgency levels and examples, yes/no criteria). Question names and types,
   the choice keys and the four urgency levels stay as shipped. English (ASCII) only.
3. **Test**: each test finding is triaged with the version in use and with the draft, one after the other.
   With the lookup `jev_eval_set.csv` (your own answer table) the result shows correct dispositions and
   urgencies before and after; **a draft that misses more true positives cannot be applied**. Without it, the
   last 33 triaged findings are used and the changes are listed.
4. **Apply** (reason required). Results record the version (`jev_questions = q-2026-10-06-r2a+c-…`) and the
   triage page shows a banner while custom questions are in use. **Back to shipped** is always available.

- **Per decision model**: a version belongs to the `[jev] model` it was saved for (e.g. `jev-1.13.0`,
  `clef-27b`); other models keep the shipped questions.
- **Export / import** a version as JSON (hash-checked; an import is a draft that must be tested).
- **Audit log**: every action in `index=jev_triage sourcetype=jev:prompt:audit` (who, when, which version, why).
- **Safe fallback**: if the version in use cannot be read or no longer passes the checks, triage uses the
  shipped questions and records the reason in `jev_enrich_errors`.
- **Test answers**: `jev_eval_set.csv` is not shipped (answers depend on your data). *Make LLM prompt for test
  answers* copies a prompt with the facts of the last 33 findings; check every row before uploading the CSV
  (Settings > Lookups > Lookup table files, app TA-jev-triage). See the Reference for the columns.
- The diagnostics file now includes the versions in use and the last 30 days of the audit log.

### Decision models other than Jev (0.9.15 – 0.9.17)
- `[jev] endpoint` (Setup page: *Endpoint*): any server with the same System One API, for example llama.cpp
  `/v1/systemone` or Cloudflare Clef. TypeSafe Jev stays the default; the API key may be empty for local servers.
- Evaluation without changing settings (admins): `jevtriage endpoint=<url> model=<name> [parallel=1-8]
  [timeout=seconds]`; results are not saved and the stored key is never sent to such an endpoint.
- On the 33 labelled findings, only **Cloudflare Clef 27B** came close to Jev (raw disposition 32/33,
  urgency 31/33). It is **usable under conditions**: recent llama.cpp started with `-b 4096 -ub 4096`,
  `confidence_threshold = 0.45`, a GPU with 24 GB or more (a 48 GB Mac works with `parallel=1 timeout=180`,
  about 20 s per call, for small volumes), and a re-check on your own data. Kev and Clef-Flash are not
  recommended (they cannot tell FP / Benign from TP). Set-up files: `tools/local-decision/` in the repository.
- ES Notes now end with the decision model and question version actually used (0.9.17).

### Other changes
- Enrichment searches refused by the search head's limit of concurrent searches are retried, so facts are not
  silently missing when many findings run at once (0.10.2).
- `jevtriage parallel=` / `timeout=` override the settings for one search (0.9.16).

## Upgrade
1. Apps > Manage Apps > *Install app from file* > `TA-jev-triage-0.10.3.spl`, tick *Upgrade app*.
   On Splunk Cloud: Apps > Upload app (self-service install, sc_admin).
2. **Restart Splunk** (new search command `jevprompt`, new KV collections `jev_prompt_versions` and
   `jev_prompt_state`, new sourcetype).
3. Settings and results are kept. Triage keeps using the shipped questions until an admin applies a version.

## Requirements and permissions
- Splunk Enterprise 10.x with ES 8.7, or Splunk Cloud with ES 8.7.
- Support mode: admins only (`edit_storage_passwords` or `admin_all_objects`, the same rule as the Setup page).
  The audit log is written through `receivers/simple` (`edit_tcp`, which admins have). Analysts only need to
  read the new KV collections (shared with everyone by default).
- A test calls Jev 4 times per test finding (counted as manual use, not limited by the daily limits).

## Tested on
- Splunk Enterprise 10.4.2 + ES 8.7.1 (BOTS v3 data, 33 labelled findings): 0.10.3, full support-mode flow
  (blocked draft, applied version, banner, export / import, revert, audit). Accuracy with the shipped
  questions unchanged: disposition 32/33, no true positive missed, urgency 31/33, within one level 33/33.
- Splunk Cloud 10.4.2604 + ES 8.7.0: passes AppInspect cloud vetting; the last functional test on Splunk Cloud
  was v0.9.14 (support mode not yet tried there).

## Known limitations
- Only the Jev questions can be edited. The LLM explanation and decision-guide prompts are planned for a later
  version.
- One role for everything: whoever can open support mode can also edit and apply (separate roles may come later).
- A version for another decision model can only be tested after switching `[jev]` to that model.
- The Setup page's version table and editor are narrow; long texts wrap (layout only).

## 主な変更

### サポートモード: Jev の質問の編集（0.10.0〜0.10.3）
Jev に送る質問には鍵がかかっています。サポートで文言を変える必要があるときは、管理者
（`edit_storage_passwords` または `admin_all_objects`）が **Setup >「プロンプト（サポート用）」** を開きます。

1. 理由と期限（既定 4 時間、最大 24 時間）を入れて **サポートモードを開始**。期限が来るか「サポートモードを終了」を
   押すと鍵が戻ります。適用済みの版はそのまま使われます。
2. 既定の質問か保存済みの版を元に **編集** して **下書きを保存**。変えられるのは文言だけです（instructions、選択肢の
   説明、Urgency の各段階と例、yes/no の基準）。質問の名前と種類、選択肢のキー、Urgency の4段階は既定のまま。
   英語（ASCII）のみ。
3. **試験**: 試験用の各 Finding を、使用中の版と下書きで順番にトリアージします。ルックアップ `jev_eval_set.csv`
   （お客様が作る正解表）があれば変更前後の正解数を表示し、**TP の見逃しが増える下書きは適用できません**。
   ない場合は直近にトリアージした33件で、変わった件を一覧にします。
4. **適用**（理由が必要）。結果に版が記録され（`jev_questions = q-2026-10-06-r2a+c-…`）、独自の質問を使っている間は
   トリアージ画面の上部に表示が出ます。**既定に戻す** はいつでも使えます。

- **判定モデルごと**: 版は保存したときの `[jev] model`（例 `jev-1.13.0`、`clef-27b`）向けです。ほかのモデルは
  既定の質問のままです。
- 版の **書き出し・読み込み**（JSON、ハッシュで改ざんを検出。読み込んだ版は下書きとなり、試験が必要）。
- **監査ログ**: すべての操作を `index=jev_triage sourcetype=jev:prompt:audit` に記録（誰が、いつ、どの版、理由）。
- **安全な戻り先**: 使用中の版が読めない、またはチェックに合わなくなった場合は既定の質問でトリアージを続け、
  理由を `jev_enrich_errors` に残します。
- **試験の正解表**: `jev_eval_set.csv` は同梱しません（正解はお客様のデータで変わるため）。
  「正解表を作る LLM 用プロンプトを作成」で直近33件の事実入りのプロンプトをコピーできます。全行を確認してから
  CSV をアップロードしてください（設定 > ルックアップ > ルックアップテーブルファイル、アプリ TA-jev-triage）。
  列はリファレンスを参照。
- 診断ファイルに、使用中の版と直近30日の監査記録を追加しました。

### Jev 以外の判定モデル（0.9.15〜0.9.17）
- `[jev] endpoint`（Setup 画面の「エンドポイント」）: 同じ System One API のサーバーを指定できます（例: llama.cpp の
  `/v1/systemone`、Cloudflare Clef）。既定は TypeSafe Jev のまま。ローカルのサーバーは API キーが空でも可。
- 設定を変えずに評価（管理者）: `jevtriage endpoint=<URL> model=<名前> [parallel=1-8] [timeout=秒]`。
  結果は保存せず、保存済みのキーをその接続先に送ることはありません。
- 正解付き33件で Jev に近い結果を出したのは **Cloudflare Clef 27B** だけでした（raw Disposition 32/33、Urgency 31/33）。
  **条件付きで利用可**: llama.cpp の新しい版を `-b 4096 -ub 4096` で起動、`confidence_threshold = 0.45`、
  24GB 以上の GPU（48GB の Mac は `parallel=1 timeout=180` で1回約20秒、少量向け）、自環境のデータで再確認。
  Kev と Clef-Flash は推奨しません（FP・Benign を TP と区別できない）。構築用の資材はリポジトリの
  `tools/local-decision/`。
- ES の Note の末尾に、実際に使った判定モデルと質問の版を記載（0.9.17）。

### その他
- Enrichment の検索が検索ヘッドの同時検索数の上限で断られた場合は再試行します。多数の Finding を同時に処理しても、
  事実が欠けたまま Jev に送られることがなくなりました（0.10.2）。
- `jevtriage parallel=` / `timeout=` で、その検索だけ設定を上書きできます（0.9.16）。

## 必要な環境と権限
- Splunk Enterprise 10.x と ES 8.7、または Splunk Cloud と ES 8.7。
- サポートモード: 管理者のみ（`edit_storage_passwords` または `admin_all_objects`。Setup 画面と同じ判定）。
  監査ログは `receivers/simple` で書き込みます（`edit_tcp`、管理者は保有）。アナリストは新しい KV コレクションを
  読めれば十分です（既定で全員に読み取りを許可）。
- 試験では、試験用の Finding 1件あたり Jev を4回呼びます（手動の利用として数え、1日の上限の対象外）。

  （適用不可の下書き、適用、画面の表示、書き出し・読み込み、既定に戻す、監査ログ）を確認。既定の質問での精度は
  従来どおり: Disposition 32/33、TP 見逃し 0、Urgency 31/33、±1 で 33/33。
- Splunk Cloud 10.4.2604 ＋ ES 8.7.0: AppInspect の Cloud 向け審査に合格。Splunk Cloud での動作確認は v0.9.14 が最新

## 既知の制限
- 編集できるのは Jev の質問だけです。LLM の説明と判断ガイドの指示文は今後の版で対応予定です。
- 権限は1つです。サポートモードを開始できる人が、編集と適用もできます（役割の分離は今後検討）。
- 別の判定モデル向けの版は、`[jev]` をそのモデルに切り替えてから試験します。
- Setup 画面の版の一覧と編集欄が狭く、長い文が折り返されます（表示のみ）。
