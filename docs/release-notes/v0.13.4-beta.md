## Highlights

### More context for the decision model (0.13.0 – 0.13.4)
Before asking the decision model, the app collects facts about each finding with SPL. New facts:

- **How a cloud account came to exist**: when the IAM user was created, by whom (a role session, a user, the root
  account) and from which address, and what it was given next (a console password, an access key, group membership,
  policies).
- **Look-alike user names**: the name imitates another account in the same logs (0/o, 1/I/l and similar).
- **Where a source address is**: the country (`iplocation`) and the network owner from Enterprise Security's ASN data.
  Hosting and cloud provider networks are named as such; AWS networks note that they may be the organisation's own
  instances. The owner needs the ES threat intelligence source `maxmind_geoip_asn_ipv4` (see *Upgrade*).
- **Threat intelligence**: a source address listed in ES's `ip_intel` (downloaded feeds, local lists) is reported with
  the list names. No match, no fact.
- **What the same person did on Windows** in the period: Security event log cleared, accounts deleted or created,
  security group changes (macro `jev_endpoint`).
- **GuardDuty**: severity, probed ports and the probing organisations, the organisation and country of the API caller.
  New macro `jev_guardduty` (Setup > Enrichment > *GuardDuty findings*, default
  `index=* sourcetype=aws:cloudwatch:guardduty`).

Every fact source says nothing when its data is missing (no ES, source disabled), and records no enrichment error.

Tested and left out, because they lowered correct verdicts on labelled findings: console sign-ins with or without MFA,
the kind of API client, active days in the previous week, and GuardDuty threat-list matches.

## Fixes (0.12.1)
- **Keys could not be read from another app**: running `jevtriage` from Search & Reporting failed with "no key saved"
  (Jev, LLM and evaluation keys). Keys are now read in this app's namespace whatever app the search runs in.
- **Wrong authentication fact**: when the Authentication data model used values other than the CIM ones
  (`success` / `failure` / `error`, e.g. the event name), a successful sign-in was described as "no successful login".
  The outcome is now stated only for CIM values.
- URLs in `dest` (e.g. a console sign-in URL) are no longer looked up as hosts.
- Hosts missing from the asset inventory are listed in one line, so they do not crowd out other facts.

## Upgrade from 0.12.x
1. Apps > Manage Apps > *Install app from file* > `second_opinion_triage-0.13.4.spl`, tick *Upgrade app*.
   On Splunk Cloud: Apps > Upload app. Restart Splunk if asked, and reload the Setup page in the browser.
2. Setup > Enrichment: point *GuardDuty findings* (macro `jev_guardduty`) at your GuardDuty data, and check that
   *Endpoint data* (macro `jev_endpoint`) includes the Windows Security events.
3. Optional, for the network owner of source addresses: in ES, enable the threat intelligence source
   `maxmind_geoip_asn_ipv4` with a free MaxMind GeoLite2 license key. In ES 8.7 the source URL is edited in
   Settings > Data inputs > *Intelligence downloads* (replace `YOUR_LICENSE_KEY` in the URL). Note that ES writes
   the download URL, key included, to `threatlist.log` in `_internal`.
4. Optional, for threat intelligence matches: enable the IP feeds you use in ES (they fill `ip_intel`).

Settings and results are kept.

## Requirements
- Splunk Enterprise 10.x with ES 8.7, or Splunk Cloud with ES 8.7.
- A key for the decision model (TypeSafe Jev by default) and, for explanations, an LLM key — your own keys,
  billed by those providers.

## Tested on
- Splunk Enterprise 10.4.2 + ES 8.7.1 (BOTS v3 data, 33 labelled findings), Jev 1.13: disposition 32/33, no true
  positive missed, urgency 31/33, within one level 33/33 — unchanged by the new facts. ASN data and an IP feed enabled;
  threat intelligence matches checked with `jevtriage dryrun=true`.
- Splunk Cloud 10.4 + ES 8.7.1: installation and Setup (0.13.2).

## Known limitations
- Threat intelligence matches cover source IP addresses only (not domains, URLs or hashes yet).
- The network owner needs the ES ASN source; the hosting provider list is built in.
- The built-in thresholds for `clef` and `gpt-6-luna` were set on 33 findings; check them on your own labelled data
  before switching models.
- Not yet listed on Splunkbase (planned for 1.0).

## 主な変更

### 判定モデルに渡す情報を追加（0.13.0〜0.13.4）
判定モデルに聞く前に、Finding ごとに SPL で事実を集めています。次の事実を追加しました。

- **クラウドのアカウントの成り立ち**: IAM ユーザーがいつ、誰に（ロールのセッション、ユーザー、root）、どのアドレスから作られたか。
  その後に与えられたもの（コンソールのパスワード、アクセスキー、グループへの所属、ポリシー）。
- **見間違えやすいユーザー名**: 同じログにある別のアカウントの名前に似せている（0/o、1/I/l など）。
- **送信元アドレスの場所**: 国（`iplocation`）と、Enterprise Security の ASN データによるネットワークの持ち主。ホスティング・
  クラウド事業者のネットワークはその旨を書き、AWS のネットワークには「組織自身のインスタンスの可能性もある」と添えます。
  持ち主には ES の脅威インテリジェンスのソース `maxmind_geoip_asn_ipv4` が必要です（「更新手順」を参照）。
- **脅威インテリジェンス**: 送信元アドレスが ES の `ip_intel`（ダウンロードしたフィード、ローカルのリスト）に載っていれば、
  リスト名を付けて伝えます。一致しなければ何も書きません。
- **同じ人物の Windows での行動**（期間内）: セキュリティのイベントログの消去、アカウントの削除・作成、セキュリティグループの
  変更（マクロ `jev_endpoint`）。
- **GuardDuty**: 重大度、探査されたポートと探査元の組織、API の呼び出し元の組織と国。新しいマクロ `jev_guardduty`
  （Setup >「Enrichment（情報収集）」>「GuardDuty の検出結果」、既定 `index=* sourcetype=aws:cloudwatch:guardduty`）。

どの事実も、データがない場合（ES でない、ソースが無効）は何も書かず、情報収集のエラーも記録しません。

試したうえで外したもの（正解付きの Finding で正しい判定を下げたため）: MFA の有無を含むコンソールのログイン、API の利用者の
種類、前の週の活動日数、GuardDuty の脅威リストとの一致。

## 修正（0.12.1）
- **別のアプリからキーが読めない**: サーチとレポートから `jevtriage` を実行すると「キーが保存されていない」というエラーに
  なりました（Jev、LLM、評価用のキー）。どのアプリから実行しても、このアプリの範囲でキーを読むようにしました。
- **誤った認証の事実**: Authentication データモデルが CIM 以外の値（例: イベント名）を使っていると、成功したログインを
  「成功したログインなし」と書いていました。CIM の値（`success` / `failure` / `error`）のときだけ書くようにしました。
- `dest` の URL（例: コンソールのログイン URL）を、ホストとして照合しないようにしました。
- 資産台帳にないホストは1行にまとめ、ほかの事実の枠を圧迫しないようにしました。

## 0.12.x からの更新手順
1. Apps > Manage Apps > Install app from file > `second_opinion_triage-0.13.4.spl`、「Upgrade app」にチェック。
   Splunk Cloud では Apps > Upload app。再起動を求められたら Splunk を再起動し、Setup 画面はブラウザで再読み込みしてください。
2. Setup >「Enrichment（情報収集）」で、「GuardDuty の検出結果」（マクロ `jev_guardduty`）を GuardDuty のデータに向け、
   「エンドポイントのデータ」（マクロ `jev_endpoint`）に Windows のセキュリティイベントが含まれることを確認します。
3. 任意（送信元アドレスのネットワークの持ち主）: ES で脅威インテリジェンスのソース `maxmind_geoip_asn_ipv4` を、MaxMind
   GeoLite2 の無料ライセンスキーで有効にします。ES 8.7 では、設定 > データ入力 >「情報ダウンロード」で URL の
   `YOUR_LICENSE_KEY` を置き換えます。ES はダウンロードした URL をキーごと `_internal` の `threatlist.log` に記録します。
4. 任意（脅威インテリジェンスとの照合）: 使う IP のフィードを ES で有効にします（`ip_intel` に入ります）。

設定と結果は引き継がれます。

## 既知の制限
- 脅威インテリジェンスとの照合は送信元の IP アドレスだけです（ドメイン・URL・ハッシュは今後）。
- ネットワークの持ち主には ES の ASN ソースが必要です。ホスティング事業者の一覧はアプリに組み込みです。
- `clef` と `gpt-6-luna` の組み込みのしきい値は33件で決めた値です。モデルを切り替える前に、自環境の正解付きデータで確認して
  ください。
- Splunkbase にはまだ掲載していません（1.0 で予定）。
