# HF Decision Model Triage and Second Opinion App v1.0.0-rc1 (release candidate)

[日本語は下にあります](#日本語)

Release candidate for 1.0.0. Changes since **v0.13.15-beta**. Package: `second_opinion_triage-1.0.0-rc1.spl`
(SHA-256 `3426aeefc29eea49a383564bcb4c3b59bd095585cd5113ec3491a946d6efe75e`).
AppInspect (precert, all checks and cloud tags): 0 failures, 0 errors.

## Highlights

### Analysts no longer read stored credentials (0.15.0) — security fix
- Before 0.15.0 the role `jev_triage_user` had `list_storage_passwords`. On many systems this lets a user read
  **other apps' and system credentials** whose ACL is readable by everyone, not only this app's keys.
- Now the app reads its keys through its own REST endpoint (`/services/second_opinion_triage/keys`), allowed by the
  new capability `jev_triage_run`. `jev_triage_user` = `jev_triage_run` only. The endpoint returns this app's Jev
  and LLM keys; the evaluation keys only to admins.
- Saving Setup sets the read ACL of the stored keys to `admin, sc_admin`.
- **Action needed when upgrading:** open Setup as an admin and press *Save* once, so the new ACL is applied. If you
  gave analysts `list_storage_passwords` yourself, remove it.

### Context and urgency (0.14.x)
- **Cloud sessions** (0.14.3): the facts say when an AWS service made the calls for an identity (`invokedBy`, not
  the console) and when the session came from SAML single sign-on.
- **GuardDuty** (0.14.0): details are narrowed to the finding's own instance or access-key user; sample findings are
  reported as samples.
- **Benign / false positive urgency is at most Low** (`[jev] benign_urgency_cap = low`), recorded in `jev_policy`.
- **Detection output** (fields the rule wrote) can be passed with `details=true`; off by default, because the rule's
  own wording pulled benign findings to true positive in measurements.

### Faster context collection (0.15.4)
- Related findings, the roll-up window and the change window filter the notable index by entity first and apply the
  ES lookups afterwards. Same facts (checked on 71 labelled findings); on Splunk Cloud these searches went from
  6–10 s to about 2 s each.
- `jev_enrich_profile` (search output only) lists the slowest context searches of a finding.

### Other
- Built-in rule for `clef` (Workers AI): threshold 0.05, no option-order check (0.15.2), re-measured on labelled
  findings. Jev stays the default model.
- App icon and logo readable on the light theme (0.15.1).
- New document: **How it works** (`docs/en/how-it-works.md`, `docs/ja/how-it-works.md`) — which ES data is read,
  which facts are passed, and which kinds of context were tried and left out.
- The documents no longer say "beta". `tools/release.sh` handles 1.x versions.

## Upgrade from 0.13.x
1. Apps > Manage Apps > *Install app from file* > `second_opinion_triage-1.0.0-rc1.spl`, tick *Upgrade app*.
   On Splunk Cloud: Apps > Upload app. Restart Splunk if asked.
2. Open **Setup** as an admin and press **Save** (applies the new key ACL).
3. Analysts need only the role `jev_triage_user` (plus their ES role). Remove `list_storage_passwords` if you added it.

Settings and results are kept.

## Requirements
- Splunk Enterprise 10.x with ES 8.7, or Splunk Cloud with ES 8.7.
- A key for the decision model (TypeSafe Jev by default) and, for explanations, an LLM key — your own keys,
  billed by those providers.

## Tested on
- Splunk Enterprise 10.4.2 + ES 8.7.1 (BOTS v3 data, 33 labelled findings), Jev 1.13: disposition 32/33, no true
  positive missed, urgency 31/33, within one level 33/33.
- Splunk Cloud 10.4 + ES 8.7.1: install, admin and analyst roles, triage, explanations and Notes.

## Known limitations
- The labelled findings are a small set; check the suggestions on your own data before relying on them.
- Threat intelligence matches cover source IP addresses only (not domains, URLs or hashes yet).
- Users with `jev_triage_run` can call the app's endpoint and receive this app's Jev and LLM keys (the same scope as
  before). Moving the whole model call into the endpoint is planned for 1.1.
- The app pages use the light theme only (dark theme planned).

## 主な変更

### アナリストが保存された資格情報を読めなくなりました（0.15.0）— セキュリティの修正
- 0.15.0 より前は、ロール `jev_triage_user` に `list_storage_passwords` が付いていました。多くの環境では、これで
  ACL が全員に読める**他のアプリやシステムの資格情報**まで読めてしまいます（このアプリのキーだけではありません）。
- アプリは自分の REST エンドポイント（`/services/second_opinion_triage/keys`）からキーを読むようになりました。
  使えるのは新しい権限 `jev_triage_run` を持つユーザーです。`jev_triage_user` は `jev_triage_run` だけになりました。
  エンドポイントが返すのはこのアプリの Jev と LLM のキーだけで、評価用のキーは管理者にだけ返します。
- Setup で保存すると、保存したキーの読み取りを `admin, sc_admin` に限ります。
- **アップグレード時の作業:** 管理者で Setup を開き、一度**保存**を押してください（新しい ACL が付きます）。
  ご自分でアナリストに `list_storage_passwords` を付けていた場合は外してください。

### 判定に渡す情報と緊急度（0.14.x）
- **クラウドのセッション**（0.14.3）: AWS のサービスが ID の代わりに実行したこと（`invokedBy`、コンソールは除く）と、
  SAML のシングルサインオンのセッションであることを事実として渡します。
- **GuardDuty**（0.14.0）: 詳細をその検出結果のインスタンス・アクセスキーのユーザーに絞り、サンプルの検出結果は
  その旨を書きます。
- **良性・FP の緊急度は最大 Low**（`[jev] benign_urgency_cap = low`）。理由は `jev_policy` に記録します。
- **検知の出力**（ルールが書いた項目）は `details=true` で渡せます。測定でルール自身の文言が良性を TP に寄せたため、
  既定はオフです。

### 情報収集を速くしました（0.15.4）
- 関連する Finding、リスク集約の期間、変更の期間の検索で、先に Finding の索引を人・ホストで絞り、ES の照合は
  そのあとにしました。結果は同じです（正解付き 71件で確認）。Splunk Cloud では1本 6〜10秒が約2秒になりました。
- `jev_enrich_profile`（検索の出力のみ）に、時間のかかった情報収集の検索を出します。

### その他
- `clef`（Workers AI）の組み込みルールを閾値 0.05・順序確認なしに（0.15.2、正解付きの Finding で測り直し）。
  既定のモデルは Jev のままです。
- アプリのアイコンとロゴをライトテーマでも見やすく（0.15.1）。
- 新しい文書: **仕組み**（`docs/ja/how-it-works.md`、`docs/en/how-it-works.md`）。ES のどのデータを読み、どの事実を
  渡し、どんな情報を試して外したかをまとめました。
- 文書から「β版」の表記を外しました。`tools/release.sh` が 1.x の版に対応しました。

## 0.13.x からのアップグレード

2. 管理者で **Setup** を開き、**保存**を押します（キーの新しい ACL が付きます）。

   場合は外してください。
