# TA-jev-triage v0.9.14-beta

[日本語は下にあります](#日本語)

Changes since **v0.9.3-beta**. Package: `TA-jev-triage-0.9.14.spl`
(SHA-256 `bfd9be682c2fcc2e11b53453fac074b142cfcb0570d73bbfdf838516af1e7f23`).
AppInspect (cloud tags, precert): 0 failures, 0 errors, 0 manual checks.

## Highlights

### Second opinion from the ES AI SOC Analyst (0.9.13, 0.9.14)
When Enterprise Security's own AI triage (AI SOC Analyst) has a result for a finding, the triage page
now shows it next to Jev's:

- **List**: an *ES AI* column with the ES AI disposition and a mark: `=` agree, `~` partly (Jev undetermined
  but leaning the same way), `!=` disagree, and a *Compared with ES AI* filter (for example: disagreements only).
- **Detail** (opens below the list), in three columns:
  1. **ES AI**: disposition, severity, confidence, summary, justification, evidence, the checks it ran
     (failed checks are marked: its conclusion may rest on less evidence) and the analysis details.
  2. **Jev**: the suggestion, signals, the context sent to Jev, LLM explanation and actions, as before.
  3. **Decision guide**: a fixed table compares the two (both TP / both not a threat / disagree / one side
     undetermined) and gives a course of action, the urgency to act on, cautions and checks.
     *Write the guide with LLM* explains why the two differ and how to decide.
     *Write the guide to ES as a Note* adds it to the finding.
- Read only: the ES AI result is never passed to Jev, and neither ES disposition nor urgency is changed.
- Environments without ES AI triage (for example on-premises) show "No ES AI result" and work as before.

### Bulk re-run (0.9.12)
Tick findings in the list (the header box selects all shown rows) and choose *Re-run triage for selected*.
Runs 8 findings per search with progress and a summary of failures.

### Better context for cloud accounts (0.9.11)
Jev now also gets:
- permission changes (AttachUserPolicy, PutUserPolicy, AddUserToGroup, …), including whether full administrator
  permissions were attached and whether the account gave them to itself;
- MFA enrolment after signing in (CreateVirtualMFADevice, EnableMFADevice) and MFA removal;
- whether other accounts used the same source IP address, whether they signed in with MFA,
  and whether there were failed sign-ins from it.

ConsoleLogin is no longer counted as a change. On the evaluation set the accuracy is unchanged
(disposition 32/33, urgency 31/33, within one level 33/33).

### Local LLMs (0.9.4, 0.9.5, 0.9.7)
OpenAI-compatible servers such as **Ollama**, vLLM and Apple Foundation Models (**macOS `fm serve`**) can write
the explanations (provider `openai`, endpoint `http://<host>:<port>/v1`). Non-streaming requests, `thinking_level`
sent as `reasoning_effort`, empty answers reported as errors. Recommended: gemma4 / qwen3 with `none`,
gpt-oss with `low`. The LLM is called by the Splunk search head, not by the browser.

### Other changes
- **Setup page** (0.9.7): reminder when changes are not saved, connection test only after saving,
  endpoint and proxy must start with `http://` or `https://`.
- **Notes** (0.9.7, 0.9.8): explanations follow the Note language; an explanation made after the Note was written
  is added as a second, explanation-only Note.
- **Support file** (0.9.9, 0.9.10): Setup page > Support > *Create diagnostics file* (12 sections, host names and
  endpoint URLs masked, key values never read). Please attach it when you report a problem.
- **LLM timeouts** are retried once (0.9.9).
- `jev_version` now records the app version (it stayed at 0.9.3).

## Upgrade
1. Apps > Manage Apps > *Install app from file* > `TA-jev-triage-0.9.14.spl`, tick *Upgrade app*.
   On Splunk Cloud: Apps > Upload app (self-service install, sc_admin).
2. Restart Splunk if asked (new search command `jevguide`, new KV fields).
3. Settings are kept. New KV fields (`jev_guide*`, `jev_note_guide*`) are added automatically.

## Requirements and permissions
- Splunk Enterprise 10.x with ES 8.7, or Splunk Cloud with ES 8.7.
- ES AI comparison: the ES AI SOC Analyst must be enabled (Splunk Cloud, Premier). The app reads the KV
  collection `missioncontrol/mc_ai_analysis` and the ES API `public/v2/findings/{id}`; writing Notes needs
  `mc_investigation_write`, as before.

## Tested on
- Splunk Enterprise 10.4.2 + ES 8.7.1 (BOTS v3 data, 33 labelled findings)
- Splunk Cloud 10.4.2604 + ES 8.7.0 with the ES AI SOC Analyst enabled

## Known limitations
- ES AI results are compared per finding; ES AI investigation-level roll-ups are not shown.
- Severity and confidence of the ES AI are read from the table at the end of its summary; a change of that
  format in a future ES version may hide them (the disposition comes from the ES API).
- The decision guide is created on demand only (no automatic guide in the response action).

## 主な変更

### ES AI SOC Analyst とのセカンドオピニオン（0.9.13、0.9.14）
Enterprise Security 純正の AI トリアージ（AI SOC Analyst）の結果がある Finding は、トリアージ画面で
Jev の結果と並べて表示します。

- **一覧**: 「ES AI」列に ES AI の Disposition と印（＝ 一致、≒ 一部一致: Jev は判別不可だが同じ向き、
  ≠ 不一致）を表示。「ES AI との比較」で絞り込めます（例: 不一致だけ）。
- **詳細**（一覧の下に開く）は3列です。
  1. **ES AI**: Disposition、Severity、確信度、サマリ、根拠、証拠、実行した確認（失敗した確認には印。
     見た目より少ない証拠で結論を出している可能性があります）、分析の詳細。
  2. **Jev**: 提案、判断材料、Jev に渡した情報、LLM の説明、操作ボタン（従来どおり）。
  3. **判断ガイド**: 2つを決まった表で比べ（両方 TP / 両方が脅威ではない / 食い違い / どちらかが判別不可）、
     推奨する対応、対応の目安とする Urgency、注意、確認の手順を表示。「LLM でガイドを作成」で食い違いの理由と
     判断の進め方を説明し、「ガイドを ES に Note として書く」で Finding に追記します。
- 読み取りのみです。ES AI の結果は Jev に渡さず、ES の Disposition と Urgency も変更しません。
- ES AI トリアージがない環境（オンプレなど）では「ES AI の判定なし」と表示し、従来どおり動作します。

### まとめて再トリアージ（0.9.12）
一覧のチェックボックスで選び（見出しのチェックボックスで表示中をすべて選択）、「選択した Finding を再トリアージ」。
8件ずつ実行し、進み具合と失敗の内訳を表示します。

### クラウドアカウントの情報を強化（0.9.11）
Jev に次の事実も渡すようにしました。
- 権限の変更（AttachUserPolicy、PutUserPolicy、AddUserToGroup など）。管理者権限の付与や自分自身への付与も明示
- ログイン後の MFA 設定（CreateVirtualMFADevice、EnableMFADevice）と MFA の削除
- 同じ送信元 IP を他のアカウントも使っているか、それらが MFA でサインインしたか、失敗したサインインがあるか

ConsoleLogin は変更として数えなくなりました。評価データでの精度は変わりません
（Disposition 32/33、Urgency 31/33、±1 で 33/33）。

### ローカルの LLM（0.9.4、0.9.5、0.9.7）
**Ollama**、vLLM、Apple Foundation Models（**macOS の `fm serve`**）などの OpenAI 互換サーバーで説明を作れます
（provider `openai`、endpoint `http://<host>:<port>/v1`）。ストリーミングなしで要求、`thinking_level` を
`reasoning_effort` として送信、空の回答はエラー扱い。推奨: gemma4・qwen3 は `none`、gpt-oss は `low`。
LLM を呼ぶのは Splunk の検索ヘッドで、ブラウザではありません。

### その他
- **Setup 画面**（0.9.7）: 未保存の変更があると表示、接続テストは保存後のみ、エンドポイントとプロキシは
  `http://` か `https://` で始まる必要あり。
- **Note**（0.9.7、0.9.8）: 説明は Note の言語で作成。Note を書いた後に作った説明は、説明だけの Note として追記。
- **診断ファイル**（0.9.9、0.9.10）: Setup 画面 > サポート > 「診断ファイルを作成」（12項目、ホスト名と
  エンドポイントの URL は伏せ字、キーの値は読まない）。問題の報告時に添付してください。
- **LLM のタイムアウト**は1回だけ再試行（0.9.9）。
- `jev_version` にアプリの版が正しく記録されるようになりました（0.9.3 のままでした）。

## 更新手順
1. Apps > Manage Apps > Install app from file > `TA-jev-triage-0.9.14.spl`、「Upgrade app」にチェック。

- ES AI との比較: ES AI SOC Analyst が有効であること（Splunk Cloud、Premier）。アプリは KV コレクション
  `missioncontrol/mc_ai_analysis` と ES API `public/v2/findings/{id}` を読みます。Note の書き込みには従来どおり
  `mc_investigation_write` が必要です。

## 既知の制限
- ES AI との比較は Finding 単位です。ES AI の Investigation 単位のまとめは表示しません。
- ES AI の Severity と確信度はサマリ末尾の表から読み取っています。将来の ES でこの形式が変わると表示されない
  可能性があります（Disposition は ES API から取得）。
- 判断ガイドは画面のボタンでのみ作成します（レスポンスアクションでの自動作成はありません）。
