# HF Decision Model Triage and Second Opinion App v0.12.0-beta (public beta)

[日本語は下にあります](#日本語)

Changes since **v0.11.6-beta**. Package: `second_opinion_triage-0.12.0.spl`
(SHA-256 `27c31c3693a7dfaa5c68746106a878c625739815582886b86c3bba35cfe0ec1d`).
AppInspect (cloud tags, precert): 0 failures, 0 errors, 0 manual checks.

## Highlights

### Decision models other than Jev, with their own rules (0.11.7 – 0.12.0)
Three decision services were evaluated on the 33 labelled findings (always answering TP would get 29/33):

| Decision model | Disposition | True positives missed | Urgency exact / within one level | Time per call |
|---|---|---|---|---|
| TypeSafe Jev 1.13 (default) | 32/33 | 0 | 31/33 / 33/33 | ~0.15 s |
| Cloudflare Workers AI `@cf/cloudflare/clef` | 31/33 | 0 | 31/33 / 33/33 | ~0.5 s |
| OpenAI Decisions API `gpt-6-luna` | 30/33 | 0 | 31/33 / 32/33 | ~0.3 s |

Jev stays the default and is still the most accurate. The other two are options when you prefer Cloudflare or
need OpenAI's data controls (US / EU processing, zero data retention).

- **Per-model rules** (`[jev] model_rules = auto`, 0.12.0): models tested on the labelled findings use their own
  confidence threshold and option-order check: `gpt-6-luna` 0.50 without order check, `clef` 0.15, `clef-27b` 0.45.
  Jev and other models use `confidence_threshold` / `order_check` as before. Override one model with
  `[model_rules:<model>]`, or set `model_rules = off` to always use the `[jev]` values. Each result records the
  rules used (`jev_rules`, shown in the detail pane), and Setup shows the rules for the configured model.
- **OpenAI Decisions API** (0.11.9): an endpoint ending in `/v1/decisions` is called in OpenAI's format
  (input and a list of choice / score / yes-no questions); answers are converted back, refusals are reported as errors.
- **Other System One servers** (0.11.7): `[jev] request_extra` (JSON fields added to each request) and
  `confidence_field` (where the server puts its confidence).
- Laya and Clef-flash were also tested and are **not recommended** (they cannot tell FP / Benign from TP).
  Details: `poc/decision-models/README.md`.

### Keys for evaluation, for support only (0.11.8 – 0.12.0)
Setup > **Evaluation keys (support)**, hidden by default and shown to admins only, holds up to two extra keys used
only by an admin's evaluation search (`jevtriage endpoint=... model=... usekey=alt|alt2`), and only for the endpoint
given in that search. They are **not used for triage and are not a fallback**: if the decision model in use fails,
triage reports the error. Leave them empty unless support asks you to evaluate another model.

## Upgrade from 0.11.x
1. Apps > Manage Apps > *Install app from file* > `second_opinion_triage-0.12.0.spl`, tick *Upgrade app*.
   On Splunk Cloud: Apps > Upload app.
2. Restart Splunk (new result field `jev_rules`).
3. Settings and results are kept. **If your decision model is `gpt-6-luna` or `clef`, its threshold now follows the
   built-in rules**; set `model_rules = off` to keep your `[jev]` values. Nothing changes for Jev.

Still on `TA-jev-triage`? Follow *Moving from TA-jev-triage* in the
[v0.11.6-beta notes](v0.11.6-beta.md) with this package.

## Requirements
- Splunk Enterprise 10.x with ES 8.7, or Splunk Cloud with ES 8.7.
- A key for the decision model (TypeSafe Jev by default) and, for explanations, an LLM key — your own keys,
  billed by those providers.

## Tested on
- Splunk Enterprise 10.4.2 + ES 8.7.1 (BOTS v3 data, 33 labelled findings): the three decision models above with
  the built-in rules, Setup. Jev accuracy unchanged.
- Splunk Cloud 10.4 + ES 8.7.1: install and Setup.

## Known limitations
- The built-in thresholds for `clef` and `gpt-6-luna` were set on 33 findings; check them on your own labelled data
  (Setup > Prompts (support) > test answers, `jev_eval_set.csv`) before switching models.
- Support-mode question versions belong to one model; a model you switch to starts with the shipped questions.
- Not yet listed on Splunkbase (planned for 1.0).

## 主な変更

### Jev 以外の判定モデルと、モデルごとの判定ルール（0.11.7〜0.12.0）
正解付きの Finding 33件で、3つの判定サービスを評価しました（すべて TP と答えた場合は 29/33）。

| 判定モデル | Disposition | TP 見逃し | Urgency 一致 / ±1 | 1回の時間 |
|---|---|---|---|---|
| TypeSafe Jev 1.13（既定） | 32/33 | 0 | 31/33 / 33/33 | 約0.15秒 |
| Cloudflare Workers AI `@cf/cloudflare/clef` | 31/33 | 0 | 31/33 / 33/33 | 約0.5秒 |
| OpenAI Decisions API `gpt-6-luna` | 30/33 | 0 | 31/33 / 32/33 | 約0.3秒 |

既定は Jev のままで、精度も最も高い結果です。Cloudflare を使いたい場合や、OpenAI のデータ管理（米国 / EU での処理、
データを保持しない設定）が必要な場合の選択肢になります。

- **モデル別の判定ルール**（`[jev] model_rules = auto`、0.12.0）: 正解付きデータで確認したモデルは、専用の確信度の
  しきい値と選択肢順の確認を使います。`gpt-6-luna` 0.50・順序確認なし、`clef` 0.15、`clef-27b` 0.45。Jev とその他の
  モデルは従来どおり `confidence_threshold` / `order_check` です。`[model_rules:<モデル>]` で個別に上書き、
  `model_rules = off` で常に `[jev]` の値を使います。使ったルールは結果に記録し（`jev_rules`、詳細欄に表示）、
  Setup 画面には設定中のモデルのルールを表示します。
- **OpenAI Decisions API**（0.11.9）: `/v1/decisions` で終わるエンドポイントは OpenAI の形式（入力と、選択・数値・
  yes/no の質問の一覧）で呼び出し、回答を変換します。回答の拒否はエラーとして表示します。
- **その他の System One 互換サーバー**（0.11.7）: `[jev] request_extra`（各要求に追加する JSON の項目）と
  `confidence_field`（サーバーが確信度を返す項目名）。
- Laya と Clef-flash も評価しましたが、**推奨しません**（FP・Benign を TP と区別できない）。詳細は
  `poc/decision-models/README.md`。

### 評価用のキー（サポート用、0.11.8〜0.12.0）
Setup の「**評価用のキー（サポート用）**」（既定で非表示、管理者のみ表示）に、追加のキーを2つまで保存できます。
使うのは管理者の評価用の検索（`jevtriage endpoint=... model=... usekey=alt|alt2`）だけで、その検索で指定した
接続先にだけ送ります。**トリアージには使わず、予備（フォールバック）でもありません。** 使用中の判定モデルが
失敗した場合はエラーになります。サポートから依頼がない限り空欄のままにしてください。

## 0.11.x からの更新手順
1. Apps > Manage Apps > Install app from file > `second_opinion_triage-0.12.0.spl`、「Upgrade app」にチェック。
   Splunk Cloud では Apps > Upload app。
2. Splunk を再起動します（結果の新しい項目 `jev_rules` のため）。
3. 設定と結果は引き継がれます。**判定モデルが `gpt-6-luna` か `clef` の場合、しきい値は組み込みのルールに従います。**
   `[jev]` の値を使い続ける場合は `model_rules = off` にしてください。Jev の動作は変わりません。

まだ `TA-jev-triage` の場合は、[v0.11.6-beta のリリースノート](v0.11.6-beta.md)の「TA-jev-triage からの移行」を
このパッケージで行ってください。

- サポートモードの質問の版はモデルごとです。切り替えた先のモデルは既定の質問から始まります。
- Splunkbase にはまだ掲載していません（1.0 で予定）。
