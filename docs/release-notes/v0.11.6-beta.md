# HF Decision Model Triage and Second Opinion App v0.11.6-beta (public beta)

First public beta. Changes since **v0.10.3-beta** (then called *TA-jev-triage*).
Package: `second_opinion_triage-0.11.6.spl`
(SHA-256 `ff72f27b7e712aa5d335feae85c3578414f3562c3d4af63f009efbc4a2aea088`).
AppInspect (cloud tags, precert): 0 failures, 0 errors, 0 manual checks.

## Highlights

### New name and app id (0.11.0, 0.11.5)
The app is now **HF Decision Model Triage and Second Opinion App** (app id `second_opinion_triage`,
formerly `TA-jev-triage`). It is a second opinion for findings in Splunk® Enterprise Security, for use alongside
the ES AI SOC Analyst; the decision model is TypeSafe Jev by default, or a compatible model.
Every display name now says **Second Opinion Triage**: the menu items of a finding, the response action,
the scheduled searches, and the titles of the Notes written to ES. Internal names are unchanged
(response action `jev_triage`, search commands, KV collections, role `jev_triage_user`).

**Because the app id changed, Splunk installs it as a new app** — see *Moving from TA-jev-triage* below.

### One click from ES: "Run Second Opinion Triage" (0.11.0)
In Enterprise Security, open the menu (⋮) of a finding and choose **Run Second Opinion Triage**.
The triage page opens, asks once, and triages the finding with the defaults on Setup > **Manual run**
(write the LLM explanation: on/off, write a Note to ES: on/off). The same defaults pre-fill the response-action
form. **Open in Second Opinion Triage** opens the finding without running anything.

### Open source (0.11.0)
Apache License 2.0 (`LICENSE`, third-party notices in `NOTICE`). Support through GitHub Issues on a
best-effort basis; security problems through GitHub's private vulnerability reporting (`SECURITY.md`).

### The decision model's own name (0.11.6)
Texts that said "Jev" now name the model that made each result: the detail pane, the decision guide, the Notes and
the instructions sent to the LLM use the model stored with the result (`jev-*` → *Jev*, `clef-27b` → *Clef 27B*), so
results of different models are labelled correctly; page headings use the model in use. Setup > Decision model >
**Display name** overrides the automatic name of the configured model (empty = automatic).

### New icon and logo (0.11.1)
A balance scale: the app list, the Splunk bar and the app bar.

## Fixes
- **Setup page could not be saved** (0.10.4, since 0.9.15): the Jev endpoint and the macro `jev_endpoint` shared one
  field, so the page showed the macro value as the endpoint and refused to save. Duplicate field ids now stop the page.
- **API keys were not shared with `jev_triage_user`** (0.11.2, since 0.9.3): the ACL is now changed through
  `configs/conf-passwords` in the namespace of the key's owner. Saving the Setup page once applies it.
- The support-mode version table and editor use the full width (0.10.4).

## Moving from TA-jev-triage
1. Keep `TA-jev-triage` installed **and enabled**, and install `second_opinion_triage-0.11.6.spl` as a new app.
   Restart Splunk.
2. Open the new app's **Setup**. At the top, **Move from TA-jev-triage**: *Check what will be copied*, then
   *Copy now* (admins; same as `| jevmigrate action=run`). It copies the settings, macros, API keys (values are never
   shown), stored results, usage counters, versions of the Jev questions and whether the scheduled searches run.
   Not copied: the lookup `jev_eval_set.csv` (upload it again) and pending response-action requests.
3. Disable or remove `TA-jev-triage` and restart Splunk. While both are enabled, both run their scheduled searches.
4. Open Setup, click **Save** once (applies the key ACL fix) and **Test connection**.
5. Update correlation searches or bookmarks that link to `/app/TA-jev-triage/...`. Correlation searches that use the
   response action keep working (internal name `jev_triage`).

New installations: install the package and follow the [Quick start](../en/quickstart.md).

## Requirements
- Splunk Enterprise 10.x with ES 8.7, or Splunk Cloud with ES 8.7.
- A TypeSafe Jev API key (or a compatible decision model) and, for explanations, an LLM API key — your own keys,
  billed by those providers. See *Data sent outside Splunk* in the [Reference](../en/reference.md).

## Tested on
- Splunk Enterprise 10.4.2 + ES 8.7.1 (BOTS v3 data, 33 labelled findings): migration, Setup, manual run, Notes, model display name.
  Accuracy unchanged: disposition 32/33, no true positive missed, urgency 31/33, within one level 33/33.
- Splunk Cloud 10.4 + ES 8.7.1 (ES AI SOC Analyst enabled): migration, Setup, manual run, comparison with ES AI.

## Known limitations
- The rename cannot be done as an in-place upgrade; use the migration above.
- `jev_eval_set.csv` is not migrated.
- Only the Jev questions can be edited in support mode (LLM prompts later).
- Not yet listed on Splunkbase (planned for 1.0).

## 主な変更

### 新しい名前とアプリ ID（0.11.0、0.11.5）
アプリ名を **HF Decision Model Triage and Second Opinion App**（アプリ ID `second_opinion_triage`、旧
`TA-jev-triage`）に変えました。Splunk® Enterprise Security の Finding に、ES AI SOC Analyst と並べて使う
セカンドオピニオンを出すアプリです。判定モデルは既定で TypeSafe Jev、互換のモデルも使えます。
表示名はすべて **Second Opinion Triage** に揃えました（Finding のメニュー、レスポンスアクション、定期検索、
ES に書く Note の見出し）。内部名（レスポンスアクション `jev_triage`、検索コマンド、KV コレクション、ロール
`jev_triage_user`）は変えていません。

**アプリ ID が変わったため、Splunk には新しいアプリとして導入されます。** 下の「TA-jev-triage からの移行」を参照してください。

### ES から1クリック:「Run Second Opinion Triage」（0.11.0）
Enterprise Security で Finding のメニュー（⋮）から **Run Second Opinion Triage** を選ぶと、トリアージ画面が開き、
確認を1回出したあと、Setup >「**手動実行**」の既定値（LLM の説明を作るか、ES に Note を書くか）でトリアージします。
同じ既定値はレスポンスアクションのフォームの初期値にも入ります。**Open in Second Opinion Triage** は実行せずに開くだけです。

### オープンソース化（0.11.0）
Apache License 2.0（`LICENSE`、同梱物の表示は `NOTICE`）。サポートは GitHub Issues でベストエフォート、
セキュリティの問題は GitHub の非公開の脆弱性報告で受け付けます（`SECURITY.md`）。

### 判定モデルの名前で表示（0.11.6）
「Jev」と書いていた文言は、その結果を作ったモデルの名前で表示します。詳細欄、判断ガイド、Note、LLM への指示は結果に記録された
モデル（`jev-*` → *Jev*、`clef-27b` → *Clef 27B*）を使うので、別のモデルの結果が混ざっていても正しく表示されます。画面の見出しは
使用中のモデルの名前です。Setup >「判定モデル」の **表示名** で、設定中のモデルの名前を上書きできます（空欄 = 自動）。

### アイコンとロゴ（0.11.1）
天秤のアイコンとロゴ（アプリ一覧、Splunk のバー、アプリバー）。

## 修正
- **Setup 画面で保存できない**（0.10.4、0.9.15 から）: Jev のエンドポイントとマクロ `jev_endpoint` が同じ欄を共有し、
  マクロの値がエンドポイントとして表示されて保存できませんでした。欄の内部名の重複は画面を開いた時点で止めるようにしました。
- **API キーが `jev_triage_user` に共有されない**（0.11.2、0.9.3 から）: キーの所有者の名前空間で
  `configs/conf-passwords` の ACL を変えるようにしました。Setup 画面で一度保存すると反映されます。
- サポートモードの版の一覧と編集欄を横幅いっぱいに（0.10.4）。

## TA-jev-triage からの移行
1. `TA-jev-triage` は導入・**有効**のまま、`second_opinion_triage-0.11.6.spl` を新しいアプリとして導入し、Splunk を再起動します。
2. 新しいアプリの **Setup** を開き、上部の **TA-jev-triage からの移行** で「コピーする内容を確認」→「コピーする」
   （管理者のみ。`| jevmigrate action=run` と同じ）。コピーするもの: 設定、マクロ、API キー（値は表示しません）、
   保存済みの結果、使用量、Jev の質問の版、定期検索を定期実行するか。コピーしないもの: ルックアップ
   `jev_eval_set.csv`（アップロードし直してください）と処理待ちのレスポンスアクションの依頼。
3. `TA-jev-triage` を無効化または削除し、Splunk を再起動します。両方が有効な間は両方の定期検索が動きます。
4. Setup 画面で一度 **保存**（キーの ACL の修正を反映）し、**接続テスト** を行います。
5. `/app/TA-jev-triage/...` へのリンクを使う相関サーチやブックマークを書き換えます。レスポンスアクションを使う相関サーチは
   そのまま動きます（内部名 `jev_triage`）。

新規に導入する場合は、パッケージを導入して [クイックスタート](../ja/quickstart.md) に沿って設定してください。
